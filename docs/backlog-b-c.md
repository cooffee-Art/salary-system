## 一、当前已具备的能力

### 后端接口（除登录外都需要 Bearer Token）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 登录，返回 JWT |
| GET | `/api/auth/me` | 当前登录人 |
| GET | `/api/employees` | 全部员工 |
| GET | `/api/employees/page` | 员工分页 + keyword + deptId/deptName |
| GET | `/api/employees/{id}` | 员工详情 |
| POST | `/api/employees` | 新增员工 |
| PUT | `/api/employees/{id}` | 修改员工 |
| DELETE | `/api/employees/{id}` | 删除/离职 |
| GET | `/api/departments` | 部门下拉 |
| GET | `/api/salaries/page` | 薪资分页（三表连查） |
| GET | `/api/salaries/report/department` | 部门月度汇总 |
| POST | `/api/salaries/generate` | 生成月度工资 |

- 默认账号：`admin / admin123`
- Token 默认 2 小时
- 业务失败仍然是 HTTP 200 + `body.code`

### C1. 数据库评审（1 天）

**做什么**

1. 用 HeidiSQL 确认四张表：
   - `sys_user`
   - `sys_department`
   - `sys_employee`
   - `sys_salary`
2. 画 ER 图：
   - 部门 1:N 员工；
   - 员工 1:N 薪资；
   - `sys_user` 独立。
3. 重点检查：
   - `sys_user.username` 唯一，密码是 BCrypt 哈希，不是明文；
   - `sys_employee.emp_no` 唯一；
   - `sys_salary.uk_emp_month(emp_id, salary_month)` 是否存在；
   - `idx_salary_month` 是否存在；
   - 外键 `fk_emp_dept`、`fk_salary_emp` 是否生效；
   - 金额是否 `DECIMAL(10,2)`；
   - `status`、`create_time` 默认值；
   - 四张表字符集/排序规则是否一致。
4. 输出 `docs/db-review.md`：ER 图、结论、索引建议、风险。

**验收**

- [ ] ER 图能讲清 1:N 关系
- [ ] 唯一约束和索引逐项有结论
- [ ] 发现的问题有修复建议

### C3. 测试用例（1 天）

**做什么** 在 `docs/test/cases.md` 写可执行用例，至少覆盖：

#### 登录鉴权

- 正确账号密码 → 200 + token
- 错误密码 → 401 业务码
- 不带 Token 访问员工/薪资接口 → HTTP 401
- 伪造/过期 Token → 401
- `/api/auth/me` 返回 admin/role

#### 员工模块

- 列表、分页、keyword、deptId/deptName 组合筛选
- current=0、size=1000 边界
- 新增：正常、重复工号、手机号非法、日期未来、部门不存在
- 修改：正常、重复工号、不存在 ID
- 删除：无薪资物理删除；有薪资转离职；重复删除
- SQL 注入关键字 `' OR 1=1 --`

#### 薪资模块

- 按月份/关键字查薪资
- 部门月度报表合计是否正确
- 生成工资：正常、重复生成、未来月份、非法月份
- 无历史薪资员工是否计入 skipped
- 离职员工是否被排除
- 生成后 `actual_pay = base_pay`

#### 契约与安全

- 业务失败是否仍是 HTTP 200 + body.code
- 401 是否返回 JSON 而不是 HTML
- CORS 预检（浏览器/Postman）
- 响应中不出现 password 字段

**验收**

- [ ] 每个用例有用例编号、前置条件、步骤、期望结果
- [ ] 覆盖正常、边界、异常、安全四类
